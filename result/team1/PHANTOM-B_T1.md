| | 問い | 脅威 |
| ---- | ---- | ---- |
| P | どうすればプロンプトインジェクションが可能か? | LLMでないため対象外 |
| H | ハルシネーションが想定を超えたらどうなるか? | LLMでないため対象外 |
| A | LLMを擬人化していないか? | LLMでないため対象外 |
| N | いつ、誰に対して、出力を説明・正当化する必要があるか? | 工場の責任者に検知結果が正しいことを説明できなければならない |

## 外部のLLMを用いたアプリケーション
### 9つの問い
| | 問い | 脅威 |
| ---- | ---- | ---- |
| P | どうすればプロンプトインジェクションが可能か? | 顧客が音声ファイルを通じて文字起こしを行い任意のプロンプトを注入できる |
| H | ハルシネーションが想定を超えたらどうなるか? | 録音した議論にない決定や内容が提示される |
| A | LLMを擬人化していないか? | 顧客が会議の意図を理解したうえでまとめたものと受け取ってしまう |
| N | いつ、誰に対して、出力を説明・正当化する必要があるか? | 顧客に対して要約した結果が正しいかどうかを文字起こしのデータを元に正当化する必要がある |
| T | 学習データに偶発的または意図的な品質問題があったらどうなるか? | 外部モデルの訓練データは把握できない |
| O | LLMはどのような判断を行い、何に対してどのような制御権を持っているか。それにより意図せず攻撃面が拡大していないか?(「エージェント型AI」のデプロイパターンでは特に重要) | 文字起こしデータから要約結果を生成する |
| M | 脅威モデリングを含め、SDL(セキュア開発ライフサイクル)のその他のセキュリティエンジニアリングを適切に実施したか? | - |
| - | LLMがアクセスできるデータ、および情報が開示され得る先を制御できているか? | 文字起こしデータがLLM APIへ送信される |
| B | LLMにはどのようなバイアスがあり、それはこのユースケースにおいて許容できるか? | 要約の結果が特定の意見に対して肯定的または否定的になる恐れがある。最終判断は顧客にゆだねるため許容可。 |

## エージェント型AIを用いたアプリケーション
### 9つの問い

| | 問い | 脅威 |
| ---- | ---- | ---- |
| P | どうすればプロンプトインジェクションが可能か? | ホテルの説明文に埋め込まれた指示からTravel Planning Agentが予約指示を誤認し、任意の予約の評価を高めたり優先することができる。 |
| H | ハルシネーションが想定を超えたらどうなるか? | 存在しないプランが掲示される。支払いや予約できていないのに完了となる。 |
| A | LLMを擬人化していないか? | Travel Planning 「Agent」と呼称しているため顧客が旅行代理店担当者と同等の対応を期待する。 |
| N | いつ、誰に対して、出力を説明・正当化する必要があるか? | 顧客に予約の推薦理由を説明する必要がある。カード会社に決済の詳細を説明する必要がある。 |
| T | 学習データに偶発的または意図的な品質問題があったらどうなるか? | 外部モデルの訓練データは把握できない。 |
| O | LLMはどのような判断を行い、何に対してどのような制御権を持っているか。それにより意図せず攻撃面が拡大していないか?(「エージェント型AI」のデプロイパターンでは特に重要) | 予約を提示し、顧客が選択した予約に基づいて決済を行う。 |
| M | 脅威モデリングを含め、SDL(セキュア開発ライフサイクル)のその他のセキュリティエンジニアリングを適切に実施したか? | - |
